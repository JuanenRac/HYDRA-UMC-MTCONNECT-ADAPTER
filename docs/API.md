# HTTP API Reference

Real Express server implemented in
[`src/server.ts`](../src/server.ts), implementing the two read-only
requests every MTConnect Agent/collector expects (ANSI/MTC1.4 envelope
shape). No framework beyond Express - the XML is hand-built, not
generated by an XML library, since the payload shape is fixed and small.

Listens on `0.0.0.0:5000` by default (`PORT` env var to override). No authentication - this mirrors how real MTConnect Agents are deployed on a factory LAN.

Both endpoints share one `Header` block (`creationTime`, `instanceId`, `bufferSize`, sequence numbers) built once per process, so `/probe` and `/current` stay consistent with each other across calls within the same run.

---

## `GET /probe`

The static device model: which HydraNodes exist and what `DataItem`s each one exposes. **Currently hardcoded to exactly one HydraNode** (`hydra_umc_1`) - a real deployment would generate this from the live robot roster via HYDRA-UMC-SERVER's own `/api/hydra-info`; this placeholder proves the HTTP surface and XML shape are spec-correct end to end.

**Response** - `200`, `Content-Type: application/xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<MTConnectDevices xmlns="urn:mtconnect.org:MTConnectDevices:1.7">
  <Header creationTime="1970-01-01T00:00:00.000Z" sender="HYDRA-UMC-MTCONNECT-ADAPTER" instanceId="1234567890" version="0.0.7" bufferSize="131072" nextSequence="1" firstSequence="1" lastSequence="1"/>
  <Devices>
    <Device id="hydra_umc_1" name="HydraNode_1" uuid="hydra-umc-node-1">
      <Description manufacturer="JuanenRac (Electro Hobby 3D)">HYDRA-UMC multi-robot micro-factory cell</Description>
      <DataItems>
        <DataItem id="execution" category="EVENT" type="EXECUTION"/>
        <DataItem id="avail" category="EVENT" type="AVAILABILITY"/>
        <DataItem id="spindle_temp" category="SAMPLE" type="TEMPERATURE" units="DEGREE_CELSIUS" nativeUnits="FAHRENHEIT"/>
      </DataItems>
    </Device>
  </Devices>
</MTConnectDevices>
```

## `GET /current`

The latest value of every `DataItem` declared in `/probe`.

**Every DataItem now goes through the same real `MachineReader` pipeline** - found in an ecosystem-wide software-improvements audit: `execution`/`avail` used to be hardcoded XML literals regardless of what `MachineReader` was configured; even wiring in a real one would have changed nothing about this response. [`src/reader.ts`](../src/reader.ts)'s `CachedReader` polls the configured `MachineReader` at most once every `minPollIntervalMs` (`POLL_INTERVAL_MS` env var, default `1000`), and [`src/dataitem.ts`](../src/dataitem.ts)'s `toDataItemReading()` converts a numeric raw value's native unit to the MTConnect-standard one ([`src/units.ts`](../src/units.ts)), classifies its quality, and stamps a real UTC timestamp - a string EVENT value (like `execution`/`avail`'s own real enumerated values) passes through unconverted. A source that throws (down/unreachable) or returns an invalid value (`null`/`NaN`/an unconvertible unit) renders that DataItem as MTConnect's own real `UNAVAILABLE` value with a real `errorCode` attribute (`NO_DATA`, `UNIT_CONVERSION_ERROR`, or `SOURCE_UNAVAILABLE`) - a real degraded response, not a 500 and not stale data.

**Two real `MachineReader` implementations exist today** (see [`.env.example`](../.env.example)):

- **`FixtureMachineReader`** (the default, no `HYDRA_UMC_SERVER_URL` set) - fixed, synthetic readings (`execution: READY`, `avail: AVAILABLE`, `spindle_temp: 140°F`), for local development or a demo with no live server reachable.
- **`HydraServerMachineReader`** ([`src/hydraServerReader.ts`](../src/hydraServerReader.ts), `HYDRA_UMC_SERVER_URL` set) - a real machine source: polls a live HYDRA-UMC-SERVER's own `GET /api/settings` (the same real, live robot roster [HYDRA-UMC-TOOL-CLI](https://github.com/JuanenRac/HYDRA-UMC-TOOL-CLI)'s own `robots` command reads) and derives real `avail`/`execution` from one real robot's own current state (`HYDRA_UMC_ROBOT_ID`, default: the first robot in the roster):
  - `avail` reflects that robot's own real `online` flag.
  - `execution` is derived from that robot's own real `playbackState`: playing+paused → `INTERRUPTED`; playing → `ACTIVE`; finished → `STOPPED`; otherwise → `READY`.
  - `spindle_temp` honestly reports no data (`NO_DATA`) - no field in HYDRA-UMC-SERVER's own robot/controller shape corresponds to a real temperature sensor yet; this is not invented data under a real-looking unit label.
  - A robot that can't be found in a reachable server's own roster, or the server itself being unreachable, both surface as the same real degraded `SOURCE_UNAVAILABLE` response below - see [`src/hydraServerReader.ts`](../src/hydraServerReader.ts)'s own doc comment for why that's an honest simplification.

**Response** - `200`, `Content-Type: application/xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<MTConnectStreams xmlns="urn:mtconnect.org:MTConnectStreams:1.7">
  <Header creationTime="1970-01-01T00:00:00.000Z" sender="HYDRA-UMC-MTCONNECT-ADAPTER" instanceId="1234567890" version="0.0.7" bufferSize="131072" nextSequence="1" firstSequence="1" lastSequence="1"/>
  <Streams>
    <DeviceStream name="HydraNode_1" uuid="hydra-umc-node-1">
      <ComponentStream component="Device" name="HydraNode_1">
        <Events>
          <Execution dataItemId="execution" timestamp="1970-01-01T00:00:00.000Z" sequence="1">READY</Execution>
          <Availability dataItemId="avail" timestamp="1970-01-01T00:00:00.000Z" sequence="1">AVAILABLE</Availability>
        </Events>
        <Samples>
          <Temperature dataItemId="spindle_temp" timestamp="1970-01-01T00:00:00.000Z" sequence="1" units="DEGREE_CELSIUS">60</Temperature>
        </Samples>
      </ComponentStream>
    </DeviceStream>
  </Streams>
</MTConnectStreams>
```

A source the `CachedReader` itself couldn't reach at all degrades **every** DataItem it would have reported this way, not just `spindle_temp` - a source that cannot be reached cannot honestly report its own execution/availability either:

```xml
<Execution dataItemId="execution" timestamp="1970-01-01T00:00:00.000Z" sequence="1" errorCode="SOURCE_UNAVAILABLE">UNAVAILABLE</Execution>
<Availability dataItemId="avail" timestamp="1970-01-01T00:00:00.000Z" sequence="1" errorCode="SOURCE_UNAVAILABLE">UNAVAILABLE</Availability>
<Temperature dataItemId="spindle_temp" timestamp="1970-01-01T00:00:00.000Z" sequence="1" errorCode="SOURCE_UNAVAILABLE">UNAVAILABLE</Temperature>
```

A single invalid *value* from an otherwise-reachable source (e.g. `NO_DATA`/`UNIT_CONVERSION_ERROR`) degrades only that one DataItem, unchanged from before.
